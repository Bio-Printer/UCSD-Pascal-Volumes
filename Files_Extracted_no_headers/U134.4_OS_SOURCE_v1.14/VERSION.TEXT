Changed since the distribution source: FILER.D.TEXT (C workfiles,
exact names; since 1.03).  Since 1.06, so that the source matches the
OS binary in use: GLOBALS.TEXT MAX_SEG = 15 (was 31: SYSCOM's segment
table must fit SYSTEM.MICRO's 16 entries) and SYSTEM.A.TEXT PRINTLOCS
without the IS_FLIPT test; and for units 13 and 14: GLOBALS.TEXT
MAXUNIT = 14, SYSSEGS.A.TEXT disk units [4,5,9..14].
Since 1.07 (revision 1.10): SYSSEGS.B.TEXT GETCMD runs a program for
another and then starts the other again (Tiny-C's pexec; LOADSEGS,
SYSCOM^.EXPANSION).  Since 1.10: SYSSEGS.B.TEXT GETCMD's $ command runs
*SYSTEM.SHELL (the Tiny-C shell; ? lists it); SYSTEM.A.TEXT FGOTOXY is
MYGOTOXY.TEXT's (132 x 45, CHR(1) X Y), so BINDER is no longer needed.
Since 1.11: SYSSEGS.B.TEXT GETCMD: S (not $) at the Command: prompt runs
*SYSTEM.SHELL; the ? prompt says S(hell.
Since 1.12: SYSSEGS.B.TEXT GETCMD's X(ecute takes a path into
sub-volumes (VOL:A/B/NAME, VOL:/A/NAME, A/NAME; \ as /: SUBEXEC): the
code file runs where it is (LOADSEGS with its block on the disk).
Since 1.13: FILER.E.TEXT KRUNCH asks for a reboot when it has moved the
running operating system, found by its segment 0's unit and block
(SYSCOM^.SEGTABLE[0]): SYSTEM.C as well as SYSTEM.PASCAL (it was: a file
named SYSTEM.PASCAL on the system disk).
